# Hermes Router

A free-tier LLM router: LiteLLM behind nginx (HTTPS) exposing one OpenAI-compatible
endpoint for Hermes, with per-alias fallback chains across three free providers.

- **This repo is the source of truth**; the live instance is deployed to `/opt/hermes-router` on the VPS.
- Edit here → `git pull` on the VPS → `docker compose up -d`.

## Architecture

```
Hermes ──HTTPS──▶ nginx :443 (<YOUR_HOST>.sslip.io)
                    │  Bearer ROUTER_API_KEY + rate limit 10 r/m
                    ▼
        LiteLLM (Docker, 127.0.0.1:4000)
          aliases: free-fast / free-general / free-coding / free-fallback
          router_settings.fallbacks: each alias → [free-fallback]
                    │
     ┌──────────────┼───────────────────┐
 Nous Portal   OpenRouter        OpenCode Zen
```

`config.yaml` is **generated by the audit**, not hand-maintained. See
[Daily auto-audit](#daily-auto-audit-0600-utc) and the live changelog page
(`https://<YOUR_HOST>.sslip.io/wiki/`, served from `/var/www/model-wiki/`).

## Aliases

| Alias | Category | Intent |
|---|---|---|
| `free-fast` | fast | light models, fast first token (lightning / flash / nano / mini) |
| `free-general` | general | high context, reasoning, general work |
| `free-coding` | coding | coding-specialized (laguna / north-mini / devstral) |
| `free-fallback` | reliable | last resort — all models eligible, **must differ from `free-general`** |

Each alias carries up to 5 chain members plus a `free-fallback` group failover.
If `free-fallback` were mapped to the same category as `free-general`, both would
produce identical chains — that is a bug; verify divergence after any ranking change.

## Providers

- **Nous Portal** — primary. Generous rate limits (~60+/min). Model IDs need the
  `:free` suffix; without it requests go to billing.
- **OpenCode Zen** — highest rate limits, but **requires a real API key**
  (`OPENCODE_FREE_API_KEY`); the old keyless `dummy-keyless` mode returns 401.
  The keyless `/zen/v1` endpoint is *not* externally usable (`FreeTierError`).
- **OpenRouter** — fallback layer only. ~20 req/min shared across all free models.
  Some IDs exist only with `:free`, some only bare, some both; a suffix heuristic
  404s, so the audit emits each model's exact per-source catalog form.

Hard rules encoded in the audit: **only models priced at exactly 0** qualify
(OpenRouter prices are strings — cast to float first), and a new model must pass a
real chat-completion smoke test before entering a chain. Catalog presence is not
proof of usability. Stealth models can vanish without notice — hence deep chains.

## Daily auto-audit (06:00 UTC)

`cron/daily-router-audit.sh` → `scripts/router_audit.py` (flock-guarded, one instance only):

1. **Fetch** — free models from OpenRouter, Nous Portal, OpenCode Zen; normalize IDs
   (strip `:free`/`-free`) for dedup, keep the exact per-source form for emission;
   image-only models excluded.
2. **Rank** — cross-source presence (3/2/1 → +30/+20/+10), context length
   (≥1M +25, ≥256K +15, ≥128K +10), provider priority
   (Nous 0 / Zen 1 / OpenRouter 2 → `+(2-p)*10`), category match +15, tools +5,
   plus a capped (+7 max) bonus from the wiki benchmark cache. Availability always
   outranks benchmark score; blacklisted models are filtered at fetch, so a high
   score can never resurrect a dead model.
3. **Diff** against the current `config.yaml`.
4. **Apply** — backup to `configs/<timestamp>/`, write, restart, health check
   (retries — container startup is slow), verify, **rollback on failure**.
5. **Changelog** — `data/changelog.json`, last 30 entries, rendered on the wiki page.

`KNOWN_BROKEN_IDS` holds proven-dead models and their spelling variants (provider
slugs differ: `thinkingmachines/` vs `thinking-machines/`): GLM-5.2 (429),
Inkling (403), Step-3.7-flash (paid), Hy3 (not free anywhere), Solar-Pro-4
(Nous 400 "missing tags"), Lyria (image).

### Verify semantics: OK / LIMITED / DEAD

Every chain member is probed at its upstream, and every alias through the router:

- **DEAD** — structural failure only: 404, `missing tags`, `not found` / `model_not_found`. Fails the audit → rollback.
- **LIMITED** — 429, Zen `FreeUsageLimitError`, transient flakes. One retry, then
  warn and keep the member: absorbing rate limits is what fallback chains are for.
- **OK** — `SMOKE-OK` returned in `content` *or* `reasoning_content` (reasoning
  models burn `max_tokens` on thinking first, so probes need a generous `max_tokens`).

A full chain walk surfaces only the last deployment's error: read failures as
chain-wide, not primary-specific. After a restart, wait ~15s + health check before
verifying — early requests hit startup cooldowns and fail spuriously.

### Manual runs

```bash
python3 scripts/router_audit.py --dry-run     # preview changes
python3 scripts/router_audit.py --apply       # deploy
python3 scripts/smoke_test.py <alias|model>   # single completion through the router
pytest -q test_router_audit.py                # local unit tests (no network)
```

## Configuration

- Secrets in `.env` (chmod 600, never committed, never logged). Template: `.env.example`.
  - `ROUTER_API_KEY` — the only key clients ever hold; provider keys stay server-side.
  - `NOUS_PORTAL_API_KEY`, `OPENROUTER_API_KEY`, `OPENCODE_FREE_API_KEY`.
- `config.yaml` — model list, retry policy, fallbacks (generated).
- `.router-key` — the router key used by the audit's own smoke tests.
- `nginx-router.conf` — TLS vhost, streaming-friendly proxy (`proxy_buffering off`),
  `/wiki/` alias to `/var/www/model-wiki/`. The rate-limit **zone must live at http
  level** in `/etc/nginx/conf.d/router-limit.conf`, not inside the server block.

## Operations

```bash
cd /opt/hermes-router
docker compose up -d                        # start / restart after changes
docker compose restart litellm              # config reload
docker compose logs -f litellm              # per-request deployment, latency, fallbacks
docker compose pull && docker compose up -d # image update
curl -s https://<YOUR_HOST>.sslip.io/health/liveliness
docker compose logs litellm | grep free-general   # which deployment served an alias
```

LiteLLM logs the chosen deployment (provider/model), latency, fallbacks and 429/5xx
errors per request. Secrets and prompt contents are not logged.

### Proving failover works

Docs promise failover only for retryable errors, and mock-testing flags are stripped
on proxy ≥1.85 — so use a real error: back up `config.yaml`, point the **first**
deployment's `api_key` at a bogus env var, restart, wait 18s + health check, then
curl the alias and confirm the response comes from deployment #2. A 401-killed
primary must be skipped; if the error names the first deployment, failover is
broken. Restore the backup afterwards. Models that die on HTTP 400 belong in the
blacklist, not in the retry policy.

## Adding a provider or model

1. Add the deployment in `config.yaml` (`api_base` + `api_key: os.environ/NAME`),
   or in `scripts/router_audit.py` (source map, blacklist, category keywords).
2. Add the key to `.env` and a valueless entry to `.env.example`.
3. `docker compose up -d`, then verify: the alias through the router **and** the
   member at its upstream.

## Hermes client config

```bash
# named provider 'router' (NOT 'custom') — the Desktop picker then sees all 4 aliases
hermes config set model.default free-general
hermes config set model.provider router
# providers.router: api + key_env + discover_models:false
#   + models: {free-general, free-fast, free-coding, free-fallback} with context_length
```

Picking a model in the Desktop UI overwrites the `model:` section of Hermes'
`config.yaml` and bypasses the router. Restore it with the two commands above.

## Layout

```
config.yaml                 generated model list + retry/fallback policy
scripts/router_audit.py     fetch → rank → diff → apply → verify → changelog
scripts/smoke_test.py       single completion probe through the router
test_router_audit.py        offline unit tests
cron/daily-router-audit.sh  06:00 UTC entry point (flock)
docker-compose.yml          litellm on 127.0.0.1:4000, read-only config, env_file
nginx-router.conf           TLS vhost + /wiki/ static alias
```

Related project on the same host: `model-wiki-automation` — the free-model wiki and
the `benchmarks-cache.json` feeding the audit's ordering bonus. Keep its
`AA_ALIASES` map in sync with the copy in `router_audit.py`.
